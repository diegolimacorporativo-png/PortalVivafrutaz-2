PROBLEMA JÁ IDENTIFICADO:
Em auth.service.ts, a rotina de upgrade de senha legada aparentemente faz:

await this.repo.updateUser(userId, { password: submitted });

Isso significa que uma senha armazenada anteriormente em texto puro continua sendo salva em texto puro, em vez de ser convertida para bcrypt.

O mesmo problema aparentemente existe para companies.

Além disso, os fluxos de:
- resetPassword
- forcePasswordChange
- changePasswordSelf

aparentemente enviam a nova senha diretamente para o repository.

OBJETIVO:
Garantir que NENHUMA senha seja persistida no banco em texto puro.

REGRAS DA CORREÇÃO:
1. Usar bcrypt, aproveitando a dependência bcryptjs já existente no projeto.
2. Criar uma função central/reutilizável para geração do hash, se isso for necessário.
3. Toda senha NOVA deve obrigatoriamente passar pelo hash antes de ser persistida.
4. Senhas existentes em bcrypt devem continuar funcionando normalmente.
5. Senhas legadas em texto puro devem continuar permitindo login, mas, após um login válido, devem ser convertidas imediatamente para bcrypt.
6. O mesmo comportamento deve existir para usuários e empresas.
7. A comparação de senha deve continuar segura usando bcrypt.compare quando a senha armazenada já estiver em bcrypt.
8. NÃO alterar a lógica de sessão, permissões, RBAC ou regras de negócio sem necessidade.
9. NÃO alterar NF-e, fiscal, financeiro, logística, pedidos ou qualquer outro módulo que não seja necessário para esta correção.
10. NÃO fazer refatoração ampla do projeto.
