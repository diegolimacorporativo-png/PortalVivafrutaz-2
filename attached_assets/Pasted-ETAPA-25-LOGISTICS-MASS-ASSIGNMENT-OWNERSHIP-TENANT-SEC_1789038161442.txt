==================================================
4. REGRA PRINCIPAL

Campos de TENANT/OWNERSHIP não devem ser aceitos cegamente do cliente.

Exemplo perigoso:

PATCH /api/logistics/routes/123

body:

{
  "empresaId": 999
}

Se isso permitir transferir a rota para outra empresa:

VULNERABILIDADE.

Outro exemplo:

PATCH /api/logistics/routes/123

{
  "driverId": 456
}

Se o motorista 456 pertence a outra empresa:

VULNERABILIDADE.

A correção deve validar a relação.

Verificar:

- empresa da rota
- motorista
- pedidos
- deliveries
- stops

Se driverId puder ser alterado:

validar que o motorista pertence ao mesmo tenant.

Se order/delivery/stop puder ser associado:

validar ownership de todos os recursos relacionados.

==================================================
6. DRIVER ASSIGNMENT

Verificar endpoints que permitem:

- atribuir motorista;
- trocar motorista;
- atribuir rota;
- alterar motorista de uma entrega;
- associar motorista a empresa.

Não confiar somente em:

driverId

Validar:

driver existe;
driver pertence ao tenant correto;
usuário tem permissão;
recurso pai pertence ao mesmo tenant.

Não criar possibilidade de:

empresa A → motorista da empresa B.
