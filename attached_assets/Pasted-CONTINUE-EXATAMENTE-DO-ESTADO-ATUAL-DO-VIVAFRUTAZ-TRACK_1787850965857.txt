PRIORIDADE 1 — GPS CONTÍNUO

Garanta que o Tracker utilize Foreground Service + FusedLocationProviderClient para manter o rastreamento funcionando com:
- aplicativo minimizado;
- tela bloqueada;
- troca para outro aplicativo;
- perda e retorno de internet;
- reinicialização do aparelho.

Preserve exatamente o contrato atual do POST /api/driver/gps.

Utilize a fila offline já criada e garanta:
- persistência das posições;
- reenvio automático;
- backoff;
- deduplicação;
- envio da posição mais recente;
- recuperação após reinicialização.

PRIORIDADE 2 — MOTORISTA PERMANECER LOGADO

O motorista deve fazer login uma única vez.

Depois disso:
- fechar o aplicativo não pode exigir novo login;
- minimizar o aplicativo não pode exigir novo login;
- reiniciar o celular não pode exigir novo login;
- o Tracker deve recuperar a sessão persistida automaticamente;
- validar /api/auth/me quando houver internet;
- não armazenar a senha do motorista.

Existe atualmente uma limitação de sessão de aproximadamente 24 horas no backend.

Analise a proposta já existente em:
vivafrutaz-tracker-android/docs/TRACKER-AUTH-PROPOSAL.md

Implemente somente uma solução segura para manter o motorista conectado além desse período.

Se for realmente necessário alterar o backend para criar renovação segura de sessão, NÃO faça uma alteração improvisada.

Antes de modificar qualquer arquivo do backend:
1. explique exatamente quais arquivos serão alterados;
2. explique como a renovação funcionará;
3. explique como a senha do motorista continuará protegida;
4. explique como isso não afetará os demais usuários do ERP;
5. aguarde aprovação.

PRIORIDADE 3 — BLOQUEIO PARA DESLIGAR O GPS

O motorista NÃO deve ter um botão comum para desligar o rastreamento.

Precisamos de uma forma administrativa segura para interromper o rastreamento quando necessário.

A interrupção deverá exigir uma senha/chave administrativa.

IMPORTANTE:
- nunca coloque a chave diretamente no APK;
- nunca coloque senha em texto puro no código;
- não crie uma senha fixa dentro do aplicativo;
- a validação deve ocorrer de forma segura no backend.

Se for necessário criar endpoint/backend para essa função:
PARE antes de alterar o backend e apresente o plano técnico para aprovação.
