APROVADO.

Vamos implementar a primeira versão do VivaFrutaz Tracker Android, mas quero começar pelo MVP mais simples e seguro possível.

IMPORTANTE:

NÃO implemente ainda:

- fila offline;
- clientPositionId;
- tabela de dispositivos;
- WebSocket;
- histórico visual novo;
- geofencing;
- novas funcionalidades administrativas;
- alterações grandes no banco;
- alterações no PWA.

Quero primeiro provar que o GPS funciona com a tela bloqueada e o aplicativo em segundo plano.

OBJETIVO DO MVP:

Criar um aplicativo Android nativo em Kotlin chamado:

VivaFrutaz Tracker

O aplicativo deverá:

1. Fazer login usando o sistema de autenticação atual do VivaFrutaz.
2. Identificar o motorista autenticado através da sessão existente.
3. Mostrar o nome do motorista.
4. Solicitar as permissões de localização necessárias.
5. Ter botão:

[ INICIAR RASTREAMENTO ]

6. Ao iniciar, iniciar um Foreground Service de localização.
7. Mostrar uma notificação persistente:

"VivaFrutaz
Rastreamento ativo"

8. Capturar localização usando Fused Location Provider.
9. Usar alta precisão.
10. Tentar obter uma atualização aproximadamente a cada 15 segundos.
11. Enviar a localização para o endpoint EXISTENTE:

POST /api/driver/gps

12. Usar exatamente o payload já aceito pelo backend:

{
  "latitude": número,
  "longitude": número,
  "accuracy": número,
  "speed": número ou null,
  "heading": número ou null
}

13. NÃO enviar driverId.
14. Deixar o backend identificar o motorista através da sessão autenticada.
15. Continuar funcionando com a tela bloqueada.
16. Continuar funcionando quando o aplicativo estiver em segundo plano.
17. Permitir encerrar o rastreamento pelo botão:

[ ENCERRAR RASTREAMENTO ]

18. Ao encerrar, parar corretamente o Foreground Service.

AUTENTICAÇÃO:

Use o sistema existente.

Endpoints:

POST /api/auth/login
GET /api/auth/me
POST /api/auth/logout

A autenticação atual usa:

express-session
connect-pg-simple
sessionId

O aplicativo precisa manter a sessão/cookie necessário para que:

POST /api/driver/gps

continue sendo reconhecido pelo backend como o motorista correto.

NÃO crie JWT.
NÃO crie outro sistema de autenticação.
NÃO coloque usuário ou senha fixa no código.

SEGURANÇA:

O backend deve continuar sendo responsável por identificar o motorista.

O aplicativo nunca deve poder escolher livremente um driverId.

ANDROID:

Utilize Kotlin nativo.

Utilize Foreground Service para localização.

Utilize Fused Location Provider.

Declare corretamente o serviço como:

foregroundServiceType="location"

Implemente corretamente as permissões exigidas pela versão do Android.

O aplicativo deve lidar corretamente com:

- localização precisa;
- GPS desligado;
- permissão negada;
- permissão concedida;
- serviço parado;
- serviço ativo.

NÃO tente esconder o rastreamento.

A notificação de rastreamento deve permanecer visível enquanto o serviço estiver ativo.
