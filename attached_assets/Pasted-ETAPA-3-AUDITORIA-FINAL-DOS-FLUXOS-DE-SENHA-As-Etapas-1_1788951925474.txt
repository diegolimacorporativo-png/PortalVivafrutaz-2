3. CONFIRMAR RESPONSABILIDADE DO HASH

Precisamos confirmar exatamente onde o hash acontece.

Por exemplo:

Auth Service
↓
Auth Repository
↓
Users Repository
↓
bcrypt.hash()
↓
Banco

E o equivalente para companies.

Confirme se existe algum caminho que bypassa os repositories.

4. LOGIN COM SENHA LEGADA

Audite a lógica que trata senhas antigas armazenadas em texto puro.

Confirme:

- senha bcrypt → bcrypt.compare()
- senha legada → comparação apropriada;
- após login legado válido → conversão para bcrypt;
- após conversão → valor persistido é bcrypt;
- não existe possibilidade de continuar salvando a senha legada em texto puro.

NÃO altere essa lógica nesta etapa.

5. RESET E TROCA DE SENHA

Confirme que:

- reset por token grava somente bcrypt;
- troca própria grava somente bcrypt;
- troca obrigatória grava somente bcrypt;
- reset administrativo grava somente bcrypt;
- criação de usuário grava somente bcrypt;
- criação de empresa grava somente bcrypt;
- alteração de senha de usuário grava somente bcrypt;
- alteração de senha de empresa grava somente bcrypt.
