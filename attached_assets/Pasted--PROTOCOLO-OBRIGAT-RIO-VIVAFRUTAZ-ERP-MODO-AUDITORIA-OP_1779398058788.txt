REGRAS ABSOLUTAS E OBRIGATÓRIAS:

==================================================================
1. SUPABASE É O ÚNICO BANCO PERMITIDO
==================================================================

O sistema DEVE usar exclusivamente o banco Supabase conectado via:

SUPABASE_DATABASE_URL

É PROIBIDO:
- usar banco local
- usar SQLite
- usar banco do Replit
- usar memória temporária
- usar fallback automático
- criar mocks persistentes
- usar DATABASE_URL alternativa
- criar fallback silencioso

Qualquer tentativa de fallback deve:
- gerar erro fatal
- abortar o boot
- registrar log crítico

Objetivo:
garantir persistência REAL e permanente no Supabase.

==================================================================
2. TODA ALTERAÇÃO DE SENHA DEVE PERSISTIR NO SUPABASE
==================================================================

BUG ATUAL IDENTIFICADO:

Ao alterar senha:
- a senha muda temporariamente
- porém no reboot volta para senha antiga

Você DEVE:
- localizar TODA lógica que sobrescreve senha no boot
- localizar qualquer "password migration"
- localizar qualquer "strategic unlock boot"
- localizar qualquer reset automático
- localizar DEFINITIVE_PASSWORD hardcoded
- localizar qualquer sincronização indevida

IMPORTANTE:
A senha alterada pelo usuário DEVE:
- persistir permanentemente no banco Supabase
- sobreviver reinícios
- sobreviver deploys
- sobreviver restart do servidor

É PROIBIDO:
- sobrescrever senha no startup
- resetar senha automaticamente
- aplicar senha hardcoded no boot
- recriar hashes automáticos

==================================================================

Isso deve incluir:

- startup hooks
- strategic unlock
- migrations automáticas
- password resets automáticos
- persistência Supabase
- fluxo completo de hash/password
- validação após reboot

A correção deve:
- persistir 100% no Supabase
- sobreviver restart
- sobreviver deploy
- sobreviver hot reload
- não depender de memória
- não depender de variáveis hardcoded
